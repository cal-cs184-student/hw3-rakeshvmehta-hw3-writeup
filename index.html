Overview

In this homework I built a physically based path tracer on top of the starter code. It has five layers that each depend on the one below. Part 1 generates camera rays through each pixel and intersects them with triangles and spheres. Part 2 adds a bounding volume hierarchy (BVH), which brings the number of intersection tests per ray from hundreds or thousands down to about 7. That speedup is what makes meshes with 100k+ triangles practical. Part 3 replaces normal shading with real radiometry: a Lambertian BSDF, emission, and two Monte Carlo estimators for direct lighting (uniform hemisphere sampling and light importance sampling). Part 4 makes the estimator recursive so light can bounce several times. It supports isolated or accumulated bounces and uses Russian roulette to end paths without biasing the result. Part 5 adds adaptive sampling, so each pixel stops taking samples once a 95% confidence interval says it has converged.

The biggest thing I learned is that rendering is mostly about estimating integrals well. Every feature after Part 2 is either a more accurate estimator or a lower-variance one. The rendering equation itself never changes. Importance sampling, Russian roulette, and adaptive sampling all spend samples where they matter, and each of them has to divide by the right probability to stay unbiased. I also saw how much of the "look" of a realistic image comes from indirect light. The ceiling of the Cornell box is completely black under direct lighting alone, and red and blue only bleed onto the bunny once the second bounce is included. Neither of those happens in a basic rasterizer.

Problems I ran into and how I solved them:

  • Area-light PDF was off by a distance factor. My direct-lighting images were too bright, so I wrote a small analytic check of AreaLight::sample_L. It computed \(\cos\theta\) with the un-normalized vector to the light, so the solid-angle PDF \(r^2 / (A\cos\theta)\) came out \(r\) times too small. In my test it returned 0.616 where 1.367 was expected, at a distance of 2.22. That made the light estimate \(r\) times too bright. Normalizing the direction before the dot product fixed it.
  • Self-intersection ("shadow acne"). Shadow rays and bounce rays start exactly on a surface, so they could hit that same surface again. I set min_t = EPS_F on every secondary ray. For light-sampling shadow rays I also set max_t = distance_to_light - EPS_F, so the light's own geometry does not count as a blocker.
  • BVH recursion that never ends. If every primitive's centroid falls on one side of the midpoint split (for example, many primitives with identical centroids), the partition makes an empty child and recursion never finishes. I detect this case and fall back to a median split with std::nth_element, which always produces two non-empty halves.
  • Rays starting inside a sphere. The near quadratic root can be behind the ray origin. When the near root is below min_t, I fall back to the far root.
  • Rendering only the direct or only the indirect light. The handout asks for these separately. I made a temporary local copy of at_least_one_bounce_radiance that skips the primary direct term and zero-bounce emission, and used it only for that one render. The submitted code keeps the normal integrator.

Part 1: Ray Generation and Scene Intersection

Ray generation and the rendering pipeline

For every pixel \((x, y)\), PathTracer::raytrace_pixel takes ns_aa samples. For each one it draws a random offset \((s_x, s_y) \in [0,1)^2\) from the grid sampler, so the sample lands somewhere inside the pixel rather than always at its corner. This gives antialiasing. It then normalizes the sample to image space with \(\left(\frac{x + s_x}{w}, \frac{y + s_y}{h}\right)\) and asks the camera for a ray through that point. The ray's depth is set to max_ray_depth, it is passed to est_radiance_global_illumination, and the returned radiance values are averaged and written into the sample buffer.

Camera::generate_ray maps the normalized point \((x, y) \in [0,1]^2\) onto a virtual sensor that sits one unit in front of the pinhole, at \(z = -1\) in camera space. The sensor spans \(\pm\tan(\text{hFov}/2)\) horizontally and \(\pm\tan(\text{vFov}/2)\) vertically, so the camera-space direction is \[ \mathbf{d}_{cam} = \Big( (2x - 1)\tan\frac{\text{hFov}}{2},\; (2y - 1)\tan\frac{\text{vFov}}{2},\; -1 \Big). \] I rotate it into world space with the camera-to-world matrix c2w and normalize it. The ray starts at the camera position, with min_t = nClip and max_t = fClip so only geometry between the clipping planes counts.

Every primitive's intersect follows the same pattern: it only accepts a hit whose \(t\) is between min_t and max_t, and when it accepts one it shrinks r.max_t to that \(t\). After testing all primitives, the last recorded hit is automatically the nearest one, because any later candidate has to be closer to pass the range check. The intersection record stores \(t\), the surface normal, the primitive, and its BSDF.

Triangle intersection (Möller–Trumbore)

I used the Möller–Trumbore algorithm. Any point on the triangle can be written with barycentric coordinates as \(\mathbf{p}_1 + b_2\mathbf{e}_1 + b_3\mathbf{e}_2\), where \(\mathbf{e}_1 = \mathbf{p}_2 - \mathbf{p}_1\) and \(\mathbf{e}_2 = \mathbf{p}_3 - \mathbf{p}_1\). Setting this equal to the ray \(\mathbf{o} + t\mathbf{d}\) gives a 3×3 linear system in the unknowns \((t, b_2, b_3)\). I solve it with Cramer's rule, written as cross and dot products. With \(\mathbf{s} = \mathbf{o} - \mathbf{p}_1\), \(\mathbf{h} = \mathbf{d}\times\mathbf{e}_2\), and \(\mathbf{q} = \mathbf{s}\times\mathbf{e}_1\): \[ \det = \mathbf{e}_1\cdot\mathbf{h}, \quad b_2 = \frac{\mathbf{s}\cdot\mathbf{h}}{\det}, \quad b_3 = \frac{\mathbf{d}\cdot\mathbf{q}}{\det}, \quad t = \frac{\mathbf{e}_2\cdot\mathbf{q}}{\det}. \] If \(|\det|\) is nearly zero, the ray is parallel to the triangle's plane and I report a miss. Otherwise I exit early as soon as a barycentric test fails (\(b_2 \notin [0,1]\), \(b_3 < 0\), or \(b_2 + b_3 > 1\)), so most misses skip the remaining work. Finally I check that \(t\) is inside the ray's valid range. On a hit, I interpolate the three vertex normals with weights \((1 - b_2 - b_3, b_2, b_3)\) to get a smooth shading normal, and update max_t. has_intersection reuses the same routine with a temporary intersection record.

Sphere intersection. Substituting the ray into \(\|\mathbf{p} - \mathbf{c}\|^2 = R^2\) gives a quadratic in \(t\). A negative discriminant means a miss. Otherwise I take the nearer root, or the farther one if the nearer root is below min_t (the ray starts inside the sphere), and check it against max_t. The normal is \((\mathbf{p} - \mathbf{c})/R\).

Part 2: Bounding Volume Hierarchy

BVH construction

BVHAccel::construct_bvh works recursively on a range [start, end) of the primitive vector:

  1. Compute the bounding box of every primitive in the range and create a node with that box.
  2. If the range has at most max_leaf_size primitives, make the node a leaf that stores the range and return.
  3. Otherwise choose the longest axis of the node's bounding box (the largest of extent.x/y/z).
  4. Use the spatial midpoint of the box along that axis as the split point. Then std::partition the primitives in place: those whose bounding-box centroid is below the split point go left, the rest go right.
  5. If the partition puts everything on one side, which happens when centroids coincide or are clustered, fall back to a median split: std::nth_element on centroid coordinate puts exactly half the primitives on each side.
  6. Recurse on [start, middle) and [middle, end) to build the left and right children.

Splitting heuristic. I chose "midpoint of the longest axis, with a median fallback." Splitting the longest axis keeps child boxes from becoming long, thin slabs, which rays would cross often. The midpoint is cheap: it needs no sorting, so each level costs \(O(n)\) through the in-place partition. It also adapts to the geometry, because clusters of primitives end up in their own tight boxes. The median fallback guarantees that every split makes progress, so recursion always terminates. I considered the surface area heuristic (SAH), which usually gives slightly faster traversal, but midpoint splitting already brought the average number of intersection tests to about 7 per ray (see below), so the extra build complexity was not worth it here.

Bounding-box test and traversal

BBox::intersect uses the slab method. For each axis I compute the \(t\) values where the ray crosses the two planes of that slab, swapping them if the direction component is negative. The ray's entry time is the largest "near" value over the three axes, and its exit time is the smallest "far" value. If entry ever exceeds exit, the ray misses. A ray parallel to an axis has a zero direction component; it only overlaps the box if its origin already lies between that axis's two planes. I also clip against the ray's own [min_t, max_t], so boxes entirely behind the current closest hit get rejected.

Traversal is recursive. If the ray misses a node's box, the whole subtree is skipped. At a leaf, every primitive is tested. At an interior node, intersect visits both children, because the nearest hit could be in either one. Since each primitive hit shrinks max_t, boxes that lie behind an already-found hit get culled automatically. has_intersection (used for shadow rays) short-circuits with || and returns on the first hit, since any blocker is enough.

Analysis. The BVH speeds up rendering by 10–43× on these moderately complex scenes, and the intersection counts explain why. Without acceleration every ray is tested against every primitive. As a result, BVH render times barely change across the three scenes, and the speedup is largest for the biggest mesh. The construction cost is negligible, at about 1.5 ms for the cow. This is also why the 50k–134k-triangle scenes above render in seconds with the BVH, while a linear scan would need about 7–18× more tests per ray than it does for the beetle.

Part 3: Direct Illumination

Building blocks

For a Lambertian surface, DiffuseBSDF::f returns \(\rho/\pi\), which is the albedo divided by \(\pi\), the same in every direction. zero_bounce_radiance returns the surface's emission, so light sources show up directly in the image. one_bounce_radiance calls one of the two direct-lighting estimators below. Both estimate the reflection equation \[ L_{out}(\mathbf{p}, \omega_o) = \int_{H^2} f(\omega_i, \omega_o)\, L_i(\mathbf{p}, \omega_i)\, \cos\theta_i \, d\omega_i \;\approx\; \frac{1}{N}\sum_{j=1}^{N} \frac{f(\omega_j, \omega_o)\, L_i(\mathbf{p}, \omega_j)\, \cos\theta_j}{p(\omega_j)}. \] All of the shading math happens in a local frame where the normal is \(+z\), so \(\cos\theta = \omega_i.z\). make_coord_space builds the object-to-world matrix and its transpose.

Implementation 1: uniform hemisphere sampling

I take \(N = \#\text{lights} \times\) ns_area_light samples, so the total matches the importance sampler and the comparison is fair. For each sample I draw a direction \(\omega_i\) uniformly from the hemisphere around the normal, which has PDF \(1/(2\pi)\). I convert it to world space and cast a ray from the hit point (with min_t = EPS_F to avoid self-hits). If the ray hits something, the radiance arriving from that direction is the hit surface's emission; non-emitters contribute zero, since this part only counts direct light. Each sample adds \(f \cdot L_i \cdot \cos\theta / (1/2\pi)\), and the total is divided by \(N\). This estimator is unbiased, but most random directions miss the small ceiling light entirely, so most samples contribute nothing and the result is very noisy.

Implementation 2: light importance sampling

Instead of sampling directions blindly, I loop over every light and sample points on the light. A point light is a delta light, so one sample is exact; an area light gets ns_area_light samples. light->sample_L returns the incoming radiance, the world direction to the sampled point, the distance to it, and the PDF in solid-angle measure, \(r^2/(A\cos\theta_{light})\). I skip samples whose direction points below the surface (\(\cos\theta_i \le 0\)). For the rest, I cast a shadow ray with min_t = EPS_F and max_t = distance - EPS_F and use has_intersection to see whether anything blocks it. Unoccluded samples add \(f \cdot L_i \cdot \cos\theta_i / p\). I average the samples for each light and sum over lights. Every sample aims at the light, so only actual occlusion produces a zero, and the variance is far lower. Point lights become possible too, which hemisphere sampling can never hit.

Uniform hemisphere sampling vs. light sampling

At the same sample budget (16 samples/pixel, 8 light samples), the hemisphere-sampled images are much noisier than the light-sampled ones. The walls and floor are covered in heavy speckle, and the soft shadows under the bunny and spheres are hard to make out. Light sampling gives clean, smooth surfaces with well-defined penumbrae. The reason is the variance of the estimator. The area light covers only a small part of the hemisphere above each point, so a uniformly chosen direction rarely hits it. Most hemisphere samples contribute zero, and the rare hits are weighted heavily (divided by \(1/2\pi\)), which produces large pixel-to-pixel swings. Light sampling draws directions in proportion to where the light actually is. Each sample contributes a value close to the true answer unless it is actually occluded, so the only variance left comes from partial visibility in the penumbra. Both methods converge to the same expected image, since both are unbiased, but light sampling gets there with far fewer samples.

Part 4: Global Illumination

Implementation of indirect lighting

Sampling the BSDF. DiffuseBSDF::sample_f draws \(\omega_i\) from the BSDF's cosine-weighted hemisphere sampler, which sets the PDF to \(\cos\theta/\pi\), and returns \(f = \rho/\pi\). Sampling in proportion to \(\cos\theta\) favors directions that actually matter for a diffuse surface.

Top level. est_radiance_global_illumination intersects the camera ray with the scene. It adds zero_bounce_radiance when bounces are being accumulated, or when max_ray_depth = 0. If the depth is above zero, it then adds at_least_one_bounce_radiance.

Recursion in at_least_one_bounce_radiance. Each ray carries a remaining depth, which starts at max_ray_depth for camera rays.

  1. If depth == 0, return black.
  2. Compute the direct lighting at this hit (one_bounce_radiance) when isAccumBounces is true, or when depth == 1. In isolated mode, this means only the deepest level of the recursion contributes light, so the image shows exactly the \(m\)-th bounce.
  3. If depth == 1, stop. No further bounces are allowed.
  4. Russian roulette. The first indirect bounce from the camera hit is always traced, so even short paths get at least one bounce of indirect light. After that, a path continues with probability \(p = 0.65\) and ends with probability 0.35.
  5. Sample an incoming direction with sample_f in the local frame, convert it to world space with o2w, and spawn a ray from the hit point with min_t = EPS_F and depth - 1.
  6. If that ray hits something, recursively compute the radiance arriving along it and add \[ \frac{f(\omega_i, \omega_o)\, L_i\, \cos\theta_i}{p(\omega_i)\cdot p_{RR}}, \] where \(p_{RR} = 1\) for the guaranteed first indirect bounce and \(0.65\) afterward. Dividing by \(p_{RR}\) makes the surviving paths make up for the ones that were stopped, so the estimator stays unbiased up to the depth cap. Because max_ray_depth is a hard cap, RR never makes a path longer than \(m\) bounces.

The 2nd and 3rd bounces. The isolated 1st bounce is ordinary direct lighting: a black ceiling, sharp shadows, and no interaction between surfaces. Average image brightness drops by about 30% from bounce 2 to bounce 3, since each bounce off a diffuse surface absorbs part of the energy and spreads the rest over the hemisphere. Bounces 4 and 5 continue that trend, getting darker and flatter each time.

Compared with rasterization: a typical rasterizer computes only the local, direct term (the 1st bounce) and fakes everything else with a constant "ambient" color. The 2nd and 3rd bounces are the physically correct version of that ambient term. They differ across the scene, so ceilings and shadow areas receive light that depends on what is around them, colors spread between nearby surfaces, and contact regions like the crease under the bunny get the correct amount of darkening. Shadows become soft fill-light areas instead of flat black or flat gray. These effects are what make the path-traced Cornell box look like a real room rather than a CG render.

Accumulated vs. isolated. The accumulated images are simply the running sum of the isolated column. Going from \(m = 0\) to \(m = 1\) adds the direct light. From \(m = 1\) to \(m = 2\) is the biggest visual change: the ceiling and shadows fill in and the image gets much brighter (mean pixel value about 93 → 118). After that, each additional bounce adds less (about 124 at \(m = 3\), 127 at \(m = 4\), 128 at \(m = 5\)), because each isolated bounce carries less energy than the one before. By \(m = 4\)–5 the accumulated image has essentially converged.

Part 5: Adaptive Sampling

What adaptive sampling is

Pixels don't all converge at the same rate. A pixel on a flat, directly lit wall gets almost the same value from every sample and settles quickly. A pixel in a penumbra or on the indirectly lit ceiling varies a lot from sample to sample and needs many more. Uniform sampling gives every pixel the same budget, which wastes samples on easy pixels. Adaptive sampling treats each pixel as a statistics problem. It keeps sampling until it is 95% confident that the pixel's mean is within a set relative tolerance of the true value, then stops and moves on.

My implementation

In raytrace_pixel, alongside the running radiance sum, I keep two running sums of each sample's illuminance \(x_k\) (Vector3D::illum()): \(s_1 = \sum x_k\) and \(s_2 = \sum x_k^2\). After every samplesPerBatch samples (when \(n > 1\)), I check for convergence: \[ \mu = \frac{s_1}{n}, \qquad \sigma^2 = \frac{1}{n-1}\left(s_2 - \frac{s_1^2}{n}\right), \qquad I = 1.96\,\frac{\sigma}{\sqrt{n}}. \] \(I\) is the half-width of the 95% confidence interval for the pixel's mean. If \(I \le \text{maxTolerance}\cdot\mu\), the pixel has converged and I break out of the loop. Otherwise sampling continues, up to the maximum ns_aa. Only checking once per batch keeps the extra statistics cost negligible. I clamp \(\sigma^2\) to be at least 0, because floating-point round-off can make it slightly negative for constant pixels. When the loop ends, the pixel's color is the radiance sum divided by the actual number of samples \(n\), and \(n\) is stored in sampleCountBuffer to produce the sample-rate image. Pixels with zero variance stop at the first check. This includes the emitter and the black background, since \(I = 0 \le\) tolerance·\(\mu\).

In short, adaptive sampling automatically spends its effort on the regions that were noisiest in the Part 4 sample-count series, the ceiling and the shadows.
